# 可控角色与游戏接入

来自双人合作关卡的可复用经验。以下为检查点，不把特定角色名字、41 根骨骼、某个动作时长或游戏分工当成通用模板。

## 导入资产

1. 保留生成原件、绑骨原件和动画原件。建立相对路径清单，列出模型、动作文件、比例、面朝方向与来源任务。
2. GLB 的 mesh、skin、joints 和 animations 都要检查；静态预览正确并不能证明导入的真蒙皮参与了运行。
3. 浏览器使用 GLTFLoader 和实际 SkinnedMesh。动画共享/克隆需保留正确 skeleton 关联，多个角色不要意外共享可变骨骼状态。
4. 包围盒统一身高，脚底对齐碰撞胶囊的底部；旋转和缩放只在一个明确的父节点做，不让每个动画各自再缩放。
5. 脚本 `inspect_glb.py` 输出局部 accessor bounds，不能用它直接当世界空间身高。用目标引擎更新矩阵后获取整个角色世界包围盒。
6. 多个动画 GLB 可能各带完整几何/贴图。可保留一份主体并提取 animation-only 文件降低加载量，但必须保证节点/骨骼名、rest pose、bind transform 一致。处理 interleaved/sparse accessors、缓冲区对齐和压缩扩展；不能盲目复制本项目的简化提取代码。

## 动画与控制器的关系

- 用户要可控关卡时，把输入接到移动/物理状态，不用相机巡游和模型轮播代替玩法。
- 实际位移由控制器驱动时，生成/导入 in-place 动画，避免 root motion 与物理同时移动导致双倍速度和滑步。
- 跳跃以离地、向上、顶点、下落、实际碰撞落地的状态驱动。落地动画不应按按键后的固定延迟触发；二段跳单独处理，不能提前表现着地。
- 需要原地转向、上半身瞄准或工具技能时，明确各动画层控制哪些骨骼。不要一边全身 AnimationMixer 写骨骼、一边程序姿势覆盖同一组关节，造成抖动。
- 生成的 jump/slash 等通用 clip 不一定适合游戏。先检查 clip 持续时间、轴向、起止姿势与实际轨迹；必要时局部使用程序动画/IK，并保持现有控制方式。

## 工具、IK、蒙皮

本项目曾出现三个独立问题：握柄位置看似正确但手掌朝向翻转、右臂朝错误方向挥动、腰部衣料被错误的手臂权重拉走。应分别定位，不能只旋转整个锤子掩盖问题。

- 查看导入骨骼真实本地轴，不假定右臂一定在 +X。围绕肩关节设计蓄力、下砸、回位弧线；使用稳定肘部 pole，保持旋转插值连续。
- 手持物跟随完整的手掌 socket 位置和旋转，不仅复制位置。检查握柄误差、手腕角度和帧间角度突变，避免工具突然翻面、横穿身体。
- 一次挥击由同一时钟驱动视觉和判定：蓄力段不命中，接触帧只结算一次，收势阶段不重复伤害。不要把默认预设动画的时间点直接当所有武器的触碰时间。
- 可绑定检查返回 true 只说明服务能完成绑定，不保证皮肤/衣服变形正确。观察待机、手臂抬高、最强攻击姿势的腰、腋下、袖口、手腕和腿部。
- 修正权重时在明确的局部区域、正确坐标系内操作，保持过渡，截断影响数后重新归一化；不要复制某个旧角色的骨骼名或固定坐标阈值。
- 回归涵盖完整动作周期，不只一张最好看的截图。记录连续多帧、接触帧、最坏姿势，验证骨骼矩阵有限且权重和接近 1。

## 碰撞与场景

- 给角色独立的物理胶囊，场景碰撞与可见表面一致。静态复杂物体可用简化网格，动态物体优先凸包/复合形状；不要对每个装饰细节做昂贵三角网格刚体。
- 两个 kinematic 玩家同时移动时，查询可能只看到上一固定步的位置。检查相向移动和冲刺，必要时对伙伴的本步规划位置做扫掠约束；靠近伙伴时不要让自动台阶跨过对方身体。
- 机关的可见 mesh 与 collider 一起运动。门还没抬完不能提前删除碰撞；投射物对薄面要做连续/扫掠检测。
- 跌落、复活、暂停、自由探索属于用户玩法选择；不因“生成游戏角色”擅自加入失败弹窗或回传功能。

## 实测交付

至少按本轮变更验证：资源加载、空闲稳定、移动/跳跃、技能、工具挂接、伙伴与场景碰撞。关卡改动要走一次正常输入的完整路径，不通过检查点传送来冒充跨过障碍。调试 API 不进入正式构建；模型和动画从本地静态资源加载，Tripo 密钥不出现在浏览器。
