# 外形与精细化

## 参考准备

- 保留原始参考，用副本裁出完整主体。多视图图集先拆分，统一背景、显示比例和中心线；不要裁掉发髻、手指、鞋底或突出配件。
- 多视角几何输入须是同一对象、相容的姿态和服装。不要混用正面站姿与背面奔跑姿势来重建一个中性角色；动作照片可单独用作姿势验收参考。
- 明确 front/back/left/right 标签；镜像图、角色自身左右和观察者左右容易混淆。无法确认的侧视图宁可先不用，不伪造标签。
- 本项目曾用约百像素宽的角色侧背图：它能约束大轮廓，但无法证明生成的针织纹、发丝和手指是忠实细节。放大或 AI 补全只能提供推断，不增加原图证据。

## 先判断问题，再花生成额度

| 观察到的问题 | 优先处理 |
| --- | --- |
| 头脸/肚子/腿的比例不对，发型剪影错误 | 改进参考图或几何提示，再生成；加贴图分辨率不能解决 |
| 少了纽扣、背带、补片或手指融合 | 检查多视图是否清晰、完整；重要配件可独立建模并挂接 |
| 形状正确但像塑料、过亮 | 检查 PBR roughness/metalness、色彩空间、光照和 tone mapping |
| 动一下腰部/衣服就被手臂扯走 | 检查蒙皮权重、骨骼映射与 IK，先不要重新生成外形 |
| 大模型放进网页就卡 | 记录真实面数、贴图、draw calls、GPU 帧率，再选择减面、LOD 或压缩 |

迭代每轮记录“主要差异→改动→证据→剩余差异”。用版本目录保留上一版，不盲目增加 face_limit 或重复提交相同提示。比较已有候选可以自行完成；若后续绑定已获授权且本轮外形符合要求，继续执行，不把“模型比对”自动变成必须等待用户批准的步骤。

## 真实网格比对

使用项目现有 Three.js/引擎查看器或 Blender 导入实际生成 GLB。基础 skill 不捆绑浏览器、GPU 或 Blender 安装；缺少查看器时，可在工作目录建立临时查看器，或告知视觉验证还缺什么。

1. 中性环境光和柔和主光、低透视或正交相机。先用三轴标记确认模型前向，再输出正面、侧面、背面；不要因为导入 yaw 与示例相同就假定正面一致。
2. 参考图和模型渲染按同一主体显示高度排版，保留宽高比，不通过横向拉伸掩盖比例差异。
3. 检查剪影、头身比、肩宽、躯干/腰腹体积、腿长，再检查服装配色、标志配件和表面材质。
4. 每张模型预览必须对应实际文件版本。服务端缩略图可以做初筛，但用户要求“建模后比对”时，应补实际网格渲染。
5. 明确区分通过、部分接近、未验证。不要把“API success”“mesh 有 8 万面”写成“外形完全还原”。

推荐在项目输出中保留：`reference-front.png`、`mesh-front.png`、`reference-back.png`、`mesh-back.png`、`comparison.png`、`review.md`。文件名/数量按实际视图调整；不需要为了满足模板生成不存在的证据。

## PBR 修正

- glTF metallicRoughness 贴图中 **G 通道是粗糙度、B 通道是金属度**。粗糙度不足会让布料/毛线像塑料。
- 有纹理时检查采样纹理与材质 factor 的共同作用；只改 factor 未必能抬高过暗的 roughness 通道。基色贴图使用 sRGB，法线和 metallicRoughness 为线性数据。
- 局部改非金属区域，避免抹掉金属扣件的材质差异。不要把已有模型的特定颜色阈值直接套到所有新角色。
- 原始 GLB 保留；修改输出到新版本。确认几何、基色、法线和动画没有无意变化。
- 本地材质调整不会增加真实毛线几何。近景需要实体纤维或缝线时，按性能预算单独建模/烘焙，而不是宣称“提高粗糙度就增加了模型细节”。
